# RP6 idle RAM comparison

Measured 2026-09-28, device local time, on the connected Retroid Pocket 6.
ROCKNIX nightly 20260927, build
`55752d441dc90caa1fa81e5e4658ba7cc6293b83`.
Kernel reported 11,737,964 KiB total RAM. This is a comparison of the existing
installations, not a prediction of memory requirements on other devices.

## Method

- Same OS boot and background host services throughout; desktop sessions were
  started separately, without rebooting the device or dropping filesystem caches.
- Order: Gaming Mode, Sway, XFCE/Xorg, Gaming Mode, Sway again.
- Five snapshots per state. Desktop sampling began after at least 30 seconds
  of settling; there was a five-second gap after each process enumeration.
- One Thunar window showing `/storage` in each desktop, using its normal window
  size: Sway tabbed/maximized, XFCE approximately 667x480. No browser, player or
  graphics benchmark was running. Keyboards were not visible; Sway kept wvkbd
  resident, whereas XFCE had not launched its on-demand Onboard keyboard.
- Read `/proc/meminfo` and every readable `/proc/PID/smaps_rollup`.
  Whole-device used memory is `MemTotal - MemAvailable`, not total minus free.
  Total process PSS apportions shared mapped pages instead of double-counting
  them as summed RSS would. These are different measurements and are not added.
- Swap usage was zero in every sample.

The active Sway runtime and service were temporarily set aside while the
preserved XFCE installation ran at its expected path. Both installations and
their homes were retained. Afterwards, the original Sway runtime/service were
restored and the RP6 was returned to Gaming Mode. Sway and EmulationStation were
active, and the desktop service was inactive.

## Results

All values are MiB. Each main value is the median of five samples; parentheses
contain the observed minimum and maximum.

| State | Whole-device used memory | Total process PSS |
| --- | ---: | ---: |
| Gaming Mode before | 1707.06 (1692.74–1715.45) | 303.99 (303.78–304.15) |
| Sway, existing compositor | 1560.92 (1554.55–1573.51) | 279.64 (278.73–279.65) |
| XFCE, direct Xorg | 1637.03 (1629.66–1640.53) | 426.12 (426.10–426.12) |
| Gaming Mode after | 1627.74 (1626.69–1631.50) | 269.03 (268.99–269.04) |
| Sway, restarted compositor | 1505.33 (1498.79–1513.74) | 240.83 (240.60–240.83) |

Against XFCE, Sway saved 146.48–185.29 MiB of mapped process memory, or about
34–43% of total process PSS. The whole-device median difference was smaller:
76.11–131.70 MiB. These percentages do not describe total physical RAM savings.

Selected process PSS from representative snapshots:

| Sway repeat | MiB | XFCE | MiB |
| --- | ---: | --- | ---: |
| Sway compositor | 47.8 | Xorg | 71.7 |
| Waybar | 35.2 | xfdesktop | 64.9 |
| Thunar | 25.0 | xfce4-session | 37.5 |
| Hidden wvkbd | 1.8 | Thunar | 12.6 |

These selected rows are not complete session totals. XFCE also ran its window
manager, panel/plugins, settings, notification and volume-monitor services.
The repeated Sway run's desktop and compositor service groups together used
about 122.9 MiB PSS; XFCE's desktop service group used about 304.2 MiB.

## Interpretation and limits

Sway was lighter in both measurements. Its first compositor had survived the
earlier video/graphics experiments and used about 84 MiB PSS; the fresh
compositor used about 48 MiB. Gaming Mode also changed after restarting the
compositor/frontend. Session history therefore affects even an idle baseline.

This is a warm-session comparison, with one XFCE launch and two Sway launches,
not a controlled cold-boot or long-term leak benchmark. Whole-device accounting
includes kernel memory, buffers, tmpfs and graphics allocations not represented
fully by process PSS. Background activity and reclaimable cache affect it too.
The absolute whole-device figures must not be treated as minimum RAM needed to
run either desktop. Rockchip and low-memory devices require their own runs.

The installed-but-idle Firefox package does not load Firefox processes, so its
large disk footprint does not explain the idle comparison. Browser/video load
was intentionally outside this baseline.

The known Sway Return-button hang remains unresolved by this measurement task;
session transitions used `systemctl stop xfce-desktop.service`.
